## Sync v2026.08.9 → v2026.09.1 — one REPLACE (captured)

Reviewed on 5 September 2026 for the gap covering **v2026.09.0** and
**v2026.09.1**. The one row below was **captured the same day**.

| # | Status | File | Embedding page(s) | What it must show | Trigger |
|---|---|---|---|---|---|
| 1 | ✅ **DONE** (was REPLACE) | `linked-data-explorer-bpmn-deploy-modal.png` | `features/bpmn-modeler.md`, `user-guide/bpmn-modeler.md` | The **restructured** modal: pinned header, scrolling body, pinned footer with the result banner riding beside the buttons. Ideally captured on a bundle with a **missing resource**, so the named-and-listed missing forms/documents and the **disabled Deploy button** are both visible — that guard is the release's substantive change, and the layout change exists because bundles now reach 48 resources | v2026.09.0 |

**Why this one is worth re-shooting.** The current image predates two changes to
the same view. The modal was restructured because it had grown past the viewport
and pushed *Deploy* and *Close* off-screen — a bundle of 48 resources no longer
fits. And it now refuses a bundle whose forms or documents are missing from local
storage, listing them by name with Deploy disabled, where previously it dropped
every miss silently and still showed a green *Resources to deploy* panel.

The second is the one a reader needs to see. Its absence produced a failure three
components away: `RipR21Process` deployed with its BPMN and twelve forms but none
of its three documents, and the RONL Business API's phase-exit approval then
rendered an ordinary form instead of the signing panel.

**Not requested, deliberately:**

- **The nine new RIP phases.** They are BPMN process definitions, and the
  [ladder page](../docs/en/linked-data-explorer/features/rip-phase-ladder.md)
  documents them as a counts table plus the modelling decisions that recur —
  parallel splits, rework placement, one exit per phase. A screenshot of one
  diagram in the Modeler would show a diagram, not a decision, and eleven would
  be absurd. The rendered phase diagram *is* worth an image, but on the RONL
  Business API side where a user meets it — and that capture already exists as
  `ronl-business-api-rip-phase-swimlane.png`.
- **The Typecheck gate, Node pins and coverage work.** CI and tooling, with no
  visible surface.
- **`linked-data-explorer-deploy-modal-clean.png`** (embedded in
  `user-guide/multilingualism.md`) is used there to illustrate interface
  language, not deploy behaviour. The restructure changes its framing, but the
  point it makes still stands, so it is left alone rather than re-shot for a
  reason unrelated to why it is on that page.

## 2026-08-29 — v2026.08.9 docs sync: no new screenshots needed

This pass (v2026.08.3 → v2026.08.9) requires **no new or replaced screenshots**,
by design rather than oversight:

- **The R2.2 bundle is deployable content, not UI.** One BPMN, nine forms and
  five document templates, consumed through the existing Deploy modal. The
  Modeler itself did not change, and the new
  `features/rip-r22-bundle.md` page embeds no figures — matching
  `rip-phase1-bundle.md`, which carried three from earlier passes and gained
  none here.
- **The R2.1 page's three existing screenshots still hold.** The canvas, deploy
  modal and MijnOmgeving captures show behaviour the rewrite did not change;
  the rewrite corrected the bundle's *path, process name and contents*, none of
  which those images assert. Their relative paths were re-depthed to
  `../../../assets/` during the rewrite, which is link repair rather than a
  re-capture.
- **`ronl:signatureRef` has no UI.** The Modeler neither reads nor writes it and
  renders no badge for it — it is hand-authored and consumed by the RONL
  Business API. There is nothing to photograph.
- **The supply-chain half of this release is pipeline configuration.** Workflow
  YAML, `renovate.json` and a ruleset; nothing rendered.

**Deploy-modal caveat for a future pass.** `rip-phase1-bundle-deploy-modal.png`
was captured when the bundle held 11 resources; it now holds 16. The figure is
illustrative of the modal rather than a resource inventory, and its caption no
longer claims a count — but if a future pass wants the count to be legible from
the image, that capture is the one to redo.
